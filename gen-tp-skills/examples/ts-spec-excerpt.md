# TS 示例使用的局部规格摘录

本文件仅保留支撑示例的规则，不是完整 TS 规格或已批准基线。来源为用户提供的 `TS DOC USD/lld.md`：页头 v0.5，修订记录最新 v0.6（2026-09-14），状态正在修订。版本未统一；正式项目须重新确认基线和接口。

## 验证边界

把 TS 整体作为黑盒。外部通过配置接口提供任务链及 N=1～16 的槽位数，通过 Router Trigger 接入业务，观察向 DTE/MU/VU 下发的任务及用户退休通知；外部返回 Core/DSA ACK、方向 Credit 和 RMEM Credit。关注命令调度和身份，不验证 Core 内部计算结果。

本摘录描述事件语义，不补齐文档遗漏的真实信号名、位宽或精确周期。

## TS-FUNC-009：任务完成

来源：LLD §1.1、§3.2.2.2–§3.2.3。

- 需要双 ACK 的任务在同一执行单元的 Core 与 DSA ACK 收齐后完成；任一侧可先到，也可同拍到达。
- 两侧任务顺序须一致，按 SID/TID 配对，完成 UID 采用 Core 侧；系统保证 ACK 不重复、有效 UID 一致，单侧未匹配事件不超过 16。
- DTE/MU/VU 各组独立，某组等待配对不阻塞其他组完成。命令被接受不代表任务完成。
- 本地完成的正文规则为逐拍 valid 事件、无 ready 反压；LLD §4 接口表仍保留 ready，需确认接口基线。

## TS-FUNC-018：普通方向 Credit

来源：LLD §1.1、§3.5.2、§3.5.4、§3.6.2.2。

- 上/下、左、右各有独立名额，初始化各为 N；local 暂不消费这些名额。
- 同一用户在生命周期内首次使用某方向时申请，后续重复使用不再扣；需要多个新方向时必须同时满足，不能只取得其中一部分。
- 已登记老请求缺资源时，其他资源满足的年轻请求可以通过；竞争相同资源时按年龄优先。
- 外部每方向每个有效周期归还一个名额，归还写入计数后再参与分配，不清用户已经取得的方向记录。
- 用户退休释放槽位并不自动归还方向名额。Router 保证归还合法，不重复或超额；模块没有重复检测及饱和保护承诺。

示例据此推导“用户退休后仍保留方向欠账”的资源前序。TS 退休条件支持该推导，但完整 Router 协议未随本文给出；正式执行前须确认 Router 没有额外的先归还约束。归还时点不能只根据 TS 内部规则自由编造。

## TS-FUNC-013/014：退休、RMEM 与复用

来源：LLD §1.1、§3.2.2.2、§3.6.2.2、§3.6.3.1.2。

- Reduce 由 Core/DSA 双 ACK 完成并允许后继推进；RMEM 归还独立恢复空间，不能替代任务完成。
- 普通模式只允许队头用户退休，且要求 Task0 至 End 全完成、RMEM 已归还、没有 DataIn 查询占用。
- 对外退休通知是一拍有效信号加 UID，无外部 ready；Router 必须接收。每次退休归还用户槽位 Credit，释放槽位。
- 启用 N 个槽位，SID 在 0～N−1 回绕；空表创建复用当前 Tail，非空新增取 next(Tail)。N=1 时复用 SID0。
- 新用户的完成/占用信息不能继承旧生命周期。系统保证无跨生命周期迟到事件；此保证不能被改写成 DUT 自动识别迟到 ACK 的要求。

## 本示例未覆盖的内容

仅用以上规则展示场景粒度。配置全过程、权重加载、Special 模式、完整 Reissue、动态 PID、复位和性能等不在示例范围。内部 FIFO 操作、精确 TG/完成竞争窗口和内部信号状态需另做层级规划。
